# Rukbat Philosophy

## Purpose

Rukbat exists to make Windows automation easier to understand, write, and maintain.

It is built on the belief that automation should be understandable not only to its author, but also to those who must read, review, and modify it later.

Rukbat does not seek to replace PowerShell or become a universal programming language. It seeks to provide a clearer way to express Windows automation.

## Clarity over Freedom

Rukbat favors a consistent, recognizable style over unrestricted expressiveness.

Different programmers should be able to read each other's programs without first learning the author's individual conventions.

Freedom of expression is valuable only when it contributes to clarity.

## Simplicity over Sophistication

Rukbat values simplicity of understanding over sophistication of language design.

A small language is not necessarily a simple language, just as concise code is not necessarily readable code.

Complexity should be justified by the practical value it provides to the programmer.

## Explicitness over Magic

Rukbat favors behavior that can be understood from the source code.

Abstraction is valuable when it removes unnecessary detail, but harmful when it conceals important behavior.

Programs should reveal their intent without requiring the reader to understand hidden mechanisms.

## Practicality over Purity

Rukbat embraces Windows as its environment rather than treating platform dependence as a defect.

Its design should be coherent without pursuing theoretical purity at the expense of practical usefulness.

The realities of Windows automation should inform the language without dictating every aspect of its design.

## Evolution with Restraint

Rukbat should evolve in response to real problems, not the desire to accumulate features.

Every addition should strengthen the language's identity rather than dilute it.

The absence of a feature is not necessarily a limitation; sometimes it is a deliberate choice.

## Guiding Principle

**Rukbat should make programs easier to understand, not merely easier to write.**
