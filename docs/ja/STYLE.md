# Rukbatスタイルガイド

[English](../STYLE.md) · [言語仕様](language.md) · [標準ライブラリ](STDLIB.md)

Rukbatのプログラム、サンプル、ドキュメント内のコードは、この規約に沿って書きます。
[言語の設計思想](../PHILOSOPHY.md)に従い、処理が明確で、動作を予測しやすく、読みやすいスクリプトを目指します。
言語の意味は言語仕様で定義します。このガイドは書き方の規約であり、構文上の制限を追加するものではありません。

## 名前の付け方を揃える

| 対象 | 規則 | 例 |
|---|---|---|
| 変数・引数・フィールド | `snake_case` | `output_path` |
| 関数・メソッド | `snake_case` | `verify_release` |
| ユーザー定義の型 | `PascalCase` | `CheckResult` |
| モジュールの別名・ソースファイル名 | `snake_case` | `release_check.rukbat` |
| すべてのスコープの`const` | `snake_case` | `max_retries` |

値や処理の意味が分かる名前を付けます。
単位が重要な値には、`timeout_ms`や`max_bytes`のように単位を含めます。
処理には動詞、真偽値には`is_valid`や`has_errors`のような名前を使います。
削除を表す`remove`など、標準ライブラリと共通する操作には同じ語を使います。

`const`も通常の変数と同じ小文字の命名に揃えます。
`const`は、その名前を通じた書き換えを禁止する指定であり、実行時に得た値にも使えます。
大文字で別種の定数を表す区別は設けません。変更する予定のない変数は`const`で宣言します。

```rukbat
const max_retries := 3
const arguments := args()
retry_count := 0
retry_count = retry_count + 1
```

初期値から型が明確に分かる宣言には`:=`を使います。
空配列やnull許容型の初期化など、型の指定が必要な場合や、型を示すと使い方が明確になる場合は`: Type =`を使います。
既存の変数への代入には`=`を使います。

## レイアウトはフォーマッタに揃える

変更を提出する前に、ソースへ`rukbat fmt`を実行します。
フォーマッタの出力を標準とし、独自の手動整形は維持しません。

- インデントは空白4文字とし、1行に1文を書きます。
- 開き波括弧は宣言や制御文と同じ行に置き、`else`と`catch`は直前の閉じ波括弧と同じ行に置きます。
- 演算子・カンマ・コロンの周囲の空白と、import・関数・制御ブロックの間の空行は、フォーマッタに従います。
- BOMなしUTF-8、LF改行で保存し、ファイル末尾に改行を置きます。

細部は[整形の仕様](language.md#formatting)に従います。
インデントの設定変更や固定の行幅制限はありません。
式が読みにくくなったら、中間の値に意味のある名前を付けるか、処理を簡単にします。
インデントは書き方の規約であり、ブロックの範囲は波括弧で決まります。

## 処理方針を表す値には名前を付ける

`http.status_200_ok`、`encoding.utf8`、`hash.sha256`など、標準ライブラリに定義済みの定数を使います。
アプリケーション固有のタイムアウト、再試行回数、終了コードなど、値だけでは意味が伝わらないものは`const`で宣言します。
宣言は必要な範囲に置き、意味が共通する場合だけ共有します。

`count := 0`、`count + 1`、`items.length == 0`のような通常の計数値は、そのまま書けます。
`zero`や`one`という名前に置き換える必要はありません。
数値の単位をコメントで補うより、名前に単位を含めます。

## 処理の流れと失敗時の動作を明確にする

importを先頭に置きます。実行開始時の処理はまとめ、上から順に追えるようにします。
補助関数は、役割を説明できる単位に分けます。意図が明確になる場合や、同じ処理の繰り返しを減らせる場合に切り出してください。
再利用する補助モジュールでは、importしただけで処理が走る構成を避けます。

外部から受け取った入力は、操作を始める前に検査します。
補助関数で呼び出し元に判断を委ねる失敗が起きたら、`Error`を投げます。
回復できる場所、または診断と終了コードを決めるコマンドの入口でcatchします。
エラーを黙って無視したり、操作に失敗したまま成功を報告したりしません。

```rukbat
const invalid_input := 2

fn require_path(value: string): void {
    if value == "" {
        throw Error {
            message: "Input path must not be empty."
        }
    }
}

try {
    require_path("")
} catch err {
    eprint(err.message)
    exit(invalid_input)
}
```

コメントには、処理の理由、制約、外部環境の前提を書きます。
[ソースからの文書生成](DOCUMENTATION.md)には`///`と`//!`を使います。
標準APIを優先し、PowerShellの直接呼び出しは必要な処理に限定します。

## レビューで規約を確認する

ソースを整形し、各エントリーポイントに`rukbat check`を実行して、関連するテストを通します。
フォーマッタは識別子を改名しないため、命名と処理の意図は別途レビューします。
現在のツールには`rukbat fmt --check`や命名規則の診断はありません。
この規約への違反だけを理由に、文法上正しいプログラムがコンパイルエラーになることはありません。
