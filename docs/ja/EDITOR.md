# エディタ機能

[English](../../docs/EDITOR.md) | [日本語目次](README.md)

信頼済みワークスペースで、保存済みの`.rukbat`ファイルを開きます。
解析には未保存のソースとインポート先も使い、PowerShellの生成や実行は行いません。
整形は編集内容を返すだけで、ファイルを直接書き換えません。
インストールとコマンドは[拡張機能ガイド](VSCODE.md)、デバッグは[デバッグガイド](DEBUGGING.md)を参照してください。

<a id="workspace-scope"></a>

## ワークスペース内の検索範囲

参照検索と名前の変更は、すべてのワークスペースフォルダーの`.rukbat`ファイルを対象にします。開いていない呼び出し元も含まれます。
探索では`.git`、`bin`、`obj`、リンク、ジャンクションを除外します。明示的なインポートは通常のモジュールローダーで処理します。
開いているファイルはディスク上の内容より未保存の内容を優先します。
ワークスペースフォルダーがなければ、エントリポイントとそのインポート先だけを検索します。範囲外の呼び出し元は自動検出できません。

関連するソースにエラーがあると、完全な結果を返せません。
無関係なエラーは、インポートを特定できる限り検索を妨げません。
読めないソース、探索の失敗、インポートを特定できなくする字句エラーは、黙って除外せずに報告します。

<a id="find-references"></a>

## 参照を検索する

**Find All References** は、解決済みの宣言を基準に、宣言、読み取り、書き込み、呼び出し、構築時のフィールド指定、型注釈、対応する型引数を検索します。
異なるスコープの同名識別子は区別します。
結果は重複を除き、URIと位置の順に並べます。宣言自体を含めるかはクライアントが選びます。

<a id="rename-a-symbol"></a>

## 名前を変更する

F2で、ユーザー定義の変数・定数、引数、ループ・catchの束縛名、関数、メソッド、構造体、フィールド、相対インポートの別名を変更します。
標準ライブラリの名前、組み込み名、`self`は変更できません。

- 他のモジュールから使える宣言にはワークスペースフォルダーが必要です。対象の宣言と編集箇所はすべてその中にある必要があります。単一ファイルモードでは、そのファイル内のローカル名だけを変更できます。
- 関連するモジュールの参照関係にリンクやジャンクションがある場合は拒否します。同じ物理ファイルが複数のモジュールパスで扱われるのを防ぐためです。
- 変更後の内容をメモリ上で検査し、識別子規則、ソースエラー、元の名前解決を確認します。変更後にコンパイルできる場合でも、再宣言や意図しない参照先の変更・隠蔽は拒否します。同じ名前を指定した場合は編集しません。
- VS Codeが編集を適用し、Undoを提供します。保存するかはクライアントが決めます。検査に失敗した場合は部分的な編集を返しません。サーバーはファイルを直接書き換えません。

<a id="documentation-and-external-data"></a>

### ドキュメントと外部データ

名前の変更は、``[`files.Record.name`]``のような解決済み短縮リンクと、独立して検査する`rukbat check`コードブロック内の参照も更新します。
コメントの接頭辞とソース位置は維持します。
通常の説明文、文字列、Markdownリンク、検査対象外の例、PowerShell文字列は変更しません。

名前解決が安全でも、外部との互換性までは保証されません。
構造体のフィールド名を変えるとJSONキーが変わり、`test_`の変更はテスト検出に影響します。
外部データや他のプロジェクトを確認し、`rukbat doc`でHTMLを再生成してください。

<a id="signature-help"></a>

## 引数ヒント

`(`や`,`の入力、呼び出し内でのカーソル移動、引数ヒントの要求で、シグネチャと現在の引数を表示します。
内側の呼び出しを閉じると外側の呼び出しに戻ります。入れ子のリテラルや引用符内のカンマでは、外側の引数位置は進みません。

ユーザー定義・インポート済み関数、メソッド、標準API、組み込み関数、配列の`append`、辞書メソッドが対象です。
対応するジェネリック操作では、合致するシグネチャを選びます。PowerShell呼び出しの可変長引数には最後の引数ラベルを使います。
引数のない呼び出しや、固定数を超えた引数には現在の引数を表示しません。
宣言、文字列、コメント、グループ化の括弧、未解決の呼び出しには表示しません。
構造体リテラルのフィールドヒントと推論型のヒントには対応していません。

未完成の呼び出しは一時コピーを使って解析しますが、診断は実際のソースを対象にします。
シグネチャには解決済みの宣言・コメントと標準カタログを使います。

<a id="language-server-protocol"></a>

## Language Server Protocol

`rukbat lsp`は標準入出力を使い、UTF-8のContent-LengthフレームとUTF-16単位の位置で通信します。
標準出力はプロトコル専用で、ログは標準エラー出力に書きます。対応する文書URIは`file:`だけです。
サーバーは全文同期を通知し、順序付きの差分編集も受け付けます。
変更、保存、クローズ、監視対象ファイルの変更で再解析します。

補完では、一時コピーの不足したメンバー名や区切り文字を補うことがあります。
構文エラーがあると一部の解析機能を使えませんが、元ソースの診断は変えません。

名前の変更には、バージョン付き`documentChanges`と、transactionalまたはtext-only-transactionalの編集対応が必要です。
Prepare Renameは範囲と名前を返しますが、ソースのバージョンを予約しません。
Renameは最新内容を再確認します。開いているファイルにはLSPのバージョン、閉じたファイルにはnullを付け、後者は応答前に読み直します。
途中の変更を検出するとContentModifiedを返します。応答後の変更との競合は、クライアントやファイルシステム側に残ります。

ドキュメントのホバーと補完は、[文書生成ツール](DOCUMENTATION.md#reading-and-maintaining-the-result)とコメントの関連付け・検査処理を共有します。
