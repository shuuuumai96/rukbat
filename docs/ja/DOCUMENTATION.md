# ソースコメントからドキュメントを生成する

[English](../../docs/DOCUMENTATION.md) | [日本語目次](README.md)

`rukbat doc`は、ソースコメントと検査済みシグネチャを1つのオフラインHTMLファイルにまとめます。
ソースや例を実行することはなく、PowerShellも必要ありません。

```powershell
rukbat doc examples/documentation/main.rukbat
rukbat doc examples/documentation/main.rukbat --output reference.html
rukbat doc examples/documentation/main.rukbat --check
```

既定の出力はエントリソースと同じ場所の`main.html`です。
`--output`には`.html`のパスを指定し、親ディレクトリは事前に作成しておきます。
`--check`は出力せずに文書を検査します。これらのオプションは併用できません。
エントリポイントと、そこから到達できるユーザーモジュールのインポート先を調べ、共有依存は1回だけ処理します。
無関係なファイルは探索せず、標準ライブラリのAPIページも埋め込みません。

<a id="writing-comments"></a>

## コメントを書く

モジュールの使い方は、最初のコードトークンより前に、連続した1つの`//!`ブロックで書きます。

```rukbat
//! File-listing utilities. Paths use the caller's working directory.
import fs
```

トップレベルの関数、構造体、変数、構造体のフィールド・メソッドの直前に、連続した`///`行を書きます。
空行や通常のコメントを挟むと、宣言との関連付けが切れます。
文書コメントのマーカーは行頭から始めます。インデントは許可されます。
ローカル変数、インポート、実行文には`///`を付けられません。

```rukbat
/// Adds the offset and returns the result.
/// Integer overflow raises Error.
fn add(value: int, offset: int): int {
    return value + offset
}
```

関数、構造体、フィールド、メソッドはコメントなしでも文書に載ります。
モジュール変数・定数は文書コメントがある場合だけ載り、モジュール内限定の性質は変わりません。定数の修飾子も保持します。
コメントには制約、エラー、副作用、使い方を書いてください。型は検査済みシグネチャから取得するため、タグで重ねて書く必要はありません。

コンパイル時にはこれらのマーカーもコメントとして扱います。`////`は通常のコメント、文字列内のマーカーは文字列の一部です。
整形はコメント本文のインデントと末尾空白を保持します。Markdownの改行用空白も含まれます。
ソースのインデントと改行は標準形式とLFに揃えます。

<a id="markdown-links-and-examples"></a>

## Markdown、リンク、コード例

本文はCommonMark形式です。マーカー直後の空白を最大1個除き、それ以降のインデントは維持します。
生のHTMLはテキストとして表示し、画像はキャプションに置き換えます。
リンクにはフラグメント、`https`、`http`、`mailto`だけを許可します。
出力はスタイルシートを内蔵し、スクリプトや外部リソースを読み込みません。

同じモジュール内の宣言には``[`add`]``、インポートしたユーザーモジュールの宣言には``[`files.list_csv`]``、構造体メンバーには``[`Listing.paths`]``でリンクします。
名前の大文字小文字を区別します。通常のCommonMark参照定義は、この短縮記法より優先されます。
標準ライブラリの名前は短縮リンクの対象外なので、標準ライブラリガイドへの通常のリンクを使います。
生成シグネチャ内のユーザー定義型は、その宣言に自動でリンクします。

通常の`rukbat`コードブロックは表示だけで、検査しません。検査する例には`check`を付けます。

~~~~text
/// ```rukbat check
/// import "./math.rukbat" as arithmetic
/// result := arithmetic.add(2, 3)
/// print(result)
/// ```
~~~~

検査対象のコードブロックは、それぞれ独立したソースファイルとして扱います。
説明対象のモジュールと必要な依存先を明示的にインポートしてください。コメントの周囲にある宣言は自動では使えません。
相対インポートはコメントを含むソースのディレクトリが基準です。エントリポイントや出力ファイルの場所ではありません。
通常のコンパイラが構文、名前、インポート、型を検査します。
例の実行、期待する出力の確認、実行時の成功の保証はしません。
失敗箇所は元のコメント行で示し、インポート先のエラーはそのソースを示します。

<a id="reading-and-maintaining-the-result"></a>

## 生成結果を読む・更新する

エントリモジュールの説明に続いて、名前順の索引と各モジュールを表示します。宣言はソース順です。
ソース位置と固定アンカーにはエントリポイントからの相対パスを使います。
生成日時やマシン固有の絶対ソースパスは出力しません。
同じソースからは、同一のBOMなしUTF-8 HTMLを生成します。

ソースエラー、文書コメントの配置エラー（`RUK6000`）、未解決の短縮リンク（`RUK6001`）、検査対象のコード例のエラーがあると、出力を置き換えません。
成功時だけ、検査と一時ファイルへの書き込みを経て既存HTMLを置き換えます。
終了コードは成功が`0`、ソース・文書のエラーが`1`、不正な引数やI/Oエラーが`2`です。
CIでは`rukbat doc main.rukbat --check`を使えます。

言語サーバーも同じ文書コメントを使い、ホバーには全文、補完には最初の段落を表示します。未保存のインポート先も対象です。
配置エラーと未解決リンクは警告として報告します。通常のコンパイラエラーで確実に名前を解決できない間は、リンクの検査を抑制します。
コード例を検査するのは`rukbat doc`と参照検索・名前変更の要求時です。通常のエディタ診断では検査しません。
インポートエラーで名前解決ができなくても、解析済み宣言のコメントはホバーで読めます。参照検索には名前解決の成功が必要です。

VS Codeの **Rukbat: Generate Documentation** はファイルを保存し、他のエディタ操作と同じコンパイラでコマンドを実行します。
`doc`と`module_doc`スニペットで文書コメントのひな形を挿入できます。
実行可能な[文書生成の例](../../examples/documentation/main.rukbat)も参照してください。
