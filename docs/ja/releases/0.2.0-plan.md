# Rukbat 0.2.0 preview 公開計画

[English](../../releases/0.2.0-plan.md)

決定日：2026年10月31日。公開目標日：2026年11月14日（日本時間）。
この文書は決定した計画を告知するものです。0.2.0の配布開始を知らせるものではありません。
日程や対象範囲を変更した場合は、この文書と英語版を更新します。

## 今回の公開範囲

0.2.0は評価用プレビューとして公開します。構造体のフィールドと`impl`のメソッドを
分離する構文変更、戻り値の型注釈を省略した宣言をvoidとする規則、既存機能の不具合修正、配布物の検証を対象とします。
void宣言の規則は11月1日に公開範囲へ追加しました。11月2日の範囲固定後は、さらに機能を追加しません。
バージョン番号はソース互換性に関わる変更を示します。本番利用の安定性を保証するものではありません。

## 公開条件と延期条件

- データ破損、誤った結果の生成、更新消失、失敗後の成功報告につながる既知の不具合を解消する。
- 全テストを実行し、生成したスクリプトをWindows PowerShell 5.1とPowerShell 7で検証する。
  CSV・JSON処理、ファイル操作、外部プロセス実行などの実用例も確認する。
- 実際に配布するZIPとVSIXでcheck/build/run/test/fmt/doc/LSPを検証する。
  VS Codeの診断、補完、整形、実行、ビルド、デバッグも確認する。
- .NET SDK・ランタイムを別途インストールしていないクリーンなWindows環境で、
  オフラインの受け入れ検証を完了する。生成物はコンパイラのない別の実行先でも確認する。
  詳細は[配布物の受け入れ条件（英語）](../../DISTRIBUTION.md#release-acceptance)に従う。
- 移行手順を用意し、延期する不具合には影響と利用可能な回避策を記載する。
  軽微な補完・表示・診断文の問題は後続版へ回せる。

候補ごとにソースのコミットと検証結果を記録します。候補を変更した場合は配布物を作り直し、
変更の影響を受ける経路とパッケージを再検証します。受け入れ検証を通過した配布物を公開します。

11月13日時点で重大な既知の不具合が残る場合、または必須検証が終わらない場合は延期します。
次の公開目標は11月21日とし、同じ公開条件を適用します。延期時にはこの計画とREADMEの告知を更新します。
日程を守るために検証を省くことはしません。

## 明示的なvoid注釈は0.3.0で削除する

2026年11月1日決定。互換期間は0.2.xに限定します。
0.2.xでは関数・メソッド宣言の`: void`を受理し、`fmt`で省略形へ変換します。
0.3.0では、この注釈の受理とフォーマッタの変換処理を削除します。
旧表記には、戻り値の型注釈を省略するよう案内する構文エラーを出します。
整形専用の旧構文パーサーも残しません。

0.2.0のリリースノートで削除予定を予告し、0.3.0へ更新する前に0.2.xの`fmt`を実行するよう案内します。
0.3.0公開までに、リポジトリ内のサンプル・文書・スニペットを移行します。
移行前の例として明示した歴史的なコード例は必要に応じて残します。
削除対象は関数・メソッド宣言の`: void`注釈だけです。
コンパイラ内部では「戻り値がない」ことをvoidとして扱い、戻り値のない呼び出しを変数へ代入するなどの誤りを検出します。
`powershell<void>`は、PowerShellの出力をRukbatの戻り値として受け取らず破棄する指定として残します。
この指定でも失敗は通常どおりErrorになります。voidは変数やフィールドに格納する値の型ではありません。
標準APIの参照表で使う`: void`は、戻り値がないことを説明する表記として残します。

## 0.1.0の扱い

- タグ、ZIP、VSIX、SHA256SUMSは、過去の環境を再現できるよう保存します。
  同じバージョン番号の配布物を別の内容へ差し替えません。
- 初期評価用プレビューであることを明記し、リリースノートに告知を追記します。
  個別の既知の不具合は、公開済みの0.1.0への影響を確認できたものだけを列挙します。
- 通常の0.1.1は予定せず、保守を0.2系に集約します。0.2.0公開前に重大なデータ破損や
  セキュリティ問題が確認された場合は、緊急修正版や該当配布物の公開停止を別途判断します。
- 0.2.0公開時に0.1.0の保守を終了します。旧版と明記して配布物を残し、後継版と移行案内へリンクします。
  英語・日本語READMEと導入案内では0.2.0を推奨します。

## 公開時に用意する移行案内

構造体内のメソッドを、同一モジュールの隣接した`impl StructName`ブロックへ移します。
フィールドだけの構造体に`impl`は不要です。新しい予約語と、ほかに確認された互換性変更も
最終リリースノートで説明します。

利用するコンパイラのバージョンを固定し、ソースを修正して`check`とテストを実行します。
再ビルドしたスクリプトを検証してから、配備済みの生成物を入れ替えます。
コンパイラの更新だけでは、既存の`.ps1`に修正は反映されません。
