# 0.1.0から0.2.0への移行案内

0.2.0は準備中です。[公開計画](0.2.0-plan.md)と
[リリースノート案（英語）](../../releases/0.2.0.md)も参照してください。

## 構造体のメソッドをimplへ移す

0.1.0で構造体内に書いていたメソッドを、同じモジュールの`impl`へ移します。
フィールドだけの構造体に変更は不要です。

移行前（0.1.0）：

```rukbat
struct Counter {
    value: int

    fn increment(): void {
        self.value = self.value + 1
    }
}
```

移行後（0.2.0）：

```rukbat
struct Counter {
    value: int
}

impl Counter {
    fn increment() {
        self.value = self.value + 1
    }
}
```

構造体と`impl`を隣接させてください。構造体ごとに`impl`は1つです。
別モジュールの型や組み込み型には追加できません。
`impl`は予約語になるため、変数名や関数名として使っている場合は変更します。
メソッドは従来どおり`counter.increment()`で呼び出します。

## 値を返さない関数では戻り値の型を省略する

関数とメソッドは、戻り値の型注釈を省略するとvoidになります。
`fn save(): void { ... }`は引き続き受理しますが、`rukbat fmt`は
`fn save() { ... }`へ統一します。既存の`: void`を手作業で消す必要はありません。

この互換措置は0.2.xだけです。**0.3.0では宣言の`: void`の受理と、fmtの変換処理を削除します。**
0.3.0へ更新する前に、0.2.xの`rukbat fmt`で移行してください。
削除後の旧表記は、省略形を案内する構文エラーになります。
コンパイラ内部では引き続きvoidで「戻り値がない」ことを扱います。
`powershell<void>`も、PowerShellの出力をRukbatの戻り値として受け取らず破棄する指定として残します。
失敗は通常どおりErrorになります。voidは変数やフィールドに格納する値の型ではありません。
詳細は[削除方針](0.2.0-plan.md#明示的なvoid注釈は030で削除する)を参照してください。

値を返す場合は、従来どおり`fn count(): int { ... }`のように型を書きます。
`fn count() { return 1 }`は型エラーです。本体から型を推論したり、末尾の式を暗黙に返したりはしません。

## 括弧と静的検査の修正に対応する

関数とメソッドの呼び出しには`()`を使います。誤って受理されていた
`helper { value }`などは拒否されます。`{}`は`Counter { value: 1 }`のような
構造体リテラルに使います。既存の予約語`while`についても、宣言やエディタでの名前変更時の検査が揃います。

要素型を推論できない配列や、ループ・メソッド呼び出しをまたぐ安全でないnullable値の使用には、
以前通っていたコードでも診断が出る場合があります。配列には必要に応じて明示的な型を指定し、
nullable値は使用時点でnullを確認してください。

文字列の比較は、ロケールに依存しない大文字小文字を区別したUTF-16列の一致として統一されます。
見た目が同じ文字列や文化依存の等価性に頼っている処理は、期待する結果をテストしてください。

## 生成物を入れ替えるまでの手順

1. 0.1.0のコンパイラ、ソース、生成済みスクリプトを退避します。
2. 0.2.0の配布開始後、コンパイラとVS Code拡張を揃えて更新します。自動処理が使うバージョンも固定します。
3. 構文を移行し、`rukbat fmt`、`rukbat check`、`rukbat test`を実行します。
4. `rukbat build`で再生成し、実際の実行先と同じ条件で出力・終了コード・ファイル更新を検証します。
5. 検証できた生成物を配備します。問題があれば退避した版へ戻します。

コンパイラの更新だけでは、既存の`.ps1`に修正は反映されません。
0.2.0公開時に0.1.0の保守は終了しますが、旧版のタグと配布物は保存します。
