# Rukbat言語仕様

[English](../../docs/language.md) | [日本語目次](README.md)

Rukbatは、Windowsのシステムスクリプト向けの型付き手続き型言語です。PowerShellとは異なる構文を使います。
コンパイルに成功すると、Windows PowerShell 5.1で単独実行できる1つの`.ps1`ファイルを生成します。

<a id="commands-and-arguments"></a>

## コマンドと引数

| コマンド | 動作 |
|---|---|
| `rukbat --version` | PowerShellを起動せず、コンパイラのバージョンを表示します。 |
| `rukbat doctor` | ポリシーを変えず、ローカルのPowerShellとネイティブヘルパーの利用可否を調べます。[配布ガイド](DISTRIBUTION.md)を参照してください。 |
| `rukbat build input.rukbat` | 検査して`input.ps1`を書き出します。 |
| `rukbat run input.rukbat -- arguments...` | ビルド後、Windows PowerShellで実行します。 |
| `rukbat check input.rukbat` | コードを生成せず、インポート、名前、型を検査します。 |
| `rukbat fmt input.rukbat` / `rukbat fmt directory` | ファイルまたはディレクトリを[標準形式に整形](#formatting)します。 |
| `rukbat test [path]` | テストを検出して実行します。[テストガイド](TESTING.md)を参照してください。 |
| `rukbat doc input.rukbat` | ソースのドキュメントを生成します。[文書生成ガイド](DOCUMENTATION.md)を参照してください。 |
| `rukbat lsp` | 言語サーバーを起動します。[エディタ機能](EDITOR.md#language-server-protocol)を参照してください。 |

`--version`と`doctor`は余分な引数を拒否します。`build`、`check`、`fmt`はプログラム用の引数を受け取りません。
コンパイル失敗時は既存の出力を変更しません。
コンパイラの成功は終了コード0、コンパイルエラーや整形時の構文エラーは1、引数やI/Oのエラーは2です。
`doctor`は成功時に0、確認の失敗や機能を利用できない場合に2を返します。
`run`は起動後にプログラムの終了コードを返し、起動失敗時には2を返します。

`args(): string[]`はエントリプログラムに渡された引数を返します。
コンパイラのコマンド、ソースパス、区切りの`--`は含みません。
`import cli`で、プログラム引数の明示的な定義、解析、ヘルプを利用できます。
特別な構文は不要で、自動の出力や終了も行いません。
APIは[標準ライブラリ](STDLIB.md)、使い方は[コマンドラインプログラム](CLI.md)を参照してください。

`exit(code: int): void`は、関数内やインポート先から呼んだ場合もプログラム全体を指定コードで終了します。
指定できる値は0～2147483647です。引数は1回評価します。
負のコードは通常のErrorになります。有効な終了コードで`exit`を呼び出すとプログラムが終了し、`catch`では捕捉できません。この呼び出しは、関数が値を返すか処理を終了しなければならない経路でも使えます。
生成スクリプトは専用のPowerShellプロセスで実行してください。exitはそのホストプロセスを終了します。

`eprint(value): void`は`print(value)`の標準エラー出力版の組み込み関数で、インポートは不要です。
どちらも同じ型検査で1個の位置引数を受け取り、プラットフォームの改行を1個追加します。関数の戻り値には混ざりません。
診断を表示しても終了コードは設定されません。
明示的な文字列変換と厳密な解析には、標準ライブラリの`text`モジュールを使います。

<a id="declarations-and-assignment"></a>

## 宣言と代入

```rukbat
name := "Taro"
age: int = 30
age = 31

fn greet(person: string): void {
    print("Hello, " + person)
}
```

- `name := value`は新しい変数を宣言し、型を推論します。
- 推論では初期化式の解決済み静的型をそのまま使います。構造体の定義元モジュール、配列、null許容型も維持します。ローカル関数、インポートした関数、`result := process.run(...)`などの標準ライブラリ呼び出しで共通です。呼び出し元モジュールで型名を解決し直すことはありません。
- `name: Type = value`は型を明示して新しい変数を宣言します。
- `name = value`は既存の変数への代入です。
- 宣言には初期値が必要です。`:=`には推論できる型が必要なので、`items := []`は不正です。
- 同じスコープ内の同名再宣言は不正です。`:=`が代入になることはありません。
- 宣言に`const`を付けると、その名前を通じた書き込みを禁止します。例は`const max_retries := 3`、`const timeout_ms: int = 5000`です。初期化は必須で、通常の実行時評価、ソース順、型規則に従います。初期化式では`args()`などの関数も呼べます。ループの各反復や関数呼び出しも含め、実行が宣言に達するたびに初期化式を1回評価します。constはコンパイル時の式評価ではありません。
- constはモジュールレベルと通常の文ブロック内で宣言できます。引数、構造体フィールド、関数宣言には付けられません。`const`は予約語です。
- const名への代入、その名前を起点とするフィールド・インデックスへの書き込み、配列の`append`、辞書の`remove`、その値を変更するメソッド呼び出しは`RUK2011`になります。入れ子の配列・構造体・辞書や、絞り込み済みのnull許容値も対象です。読み取りと値を変更しないメソッドは使えます。メソッドの変更判定は名前解決後に行います。`self`やそのフィールド・インデックスへの書き込み、self経由のappend・remove、selfを起点とした変更メソッドの間接呼び出しを伝播し、再帰やインポート先のメソッドも調べます。到達しない分岐の書き込みも含めて全経路を数え、実行時の到達可能性は推論しません。
- 通常の代入、引数、戻り値、ループ変数への束縛は値をコピーします。constの値を通常の変数や引数にコピーした場合、そのコピーは変更できます。constは宣言名への制約であり、新しい型ではありません。モジュールのconst値も通常の変数と同じくモジュール内限定です。
- 関数宣言の構文は`fn`だけです。独立した関数はモジュールスコープ、メソッドは`impl`宣言内に定義します。構造体のフィールドとメソッドは別のブロックに書きます。

名前は大文字小文字を区別します。文は改行または`;`で区切り、ブロックは波括弧で囲みます。
行コメントは`//`から行末までです。ブロックコメントには対応しません。
文字列内のコメント記号は文字列の一部です。文字列と`//`コメントの外では`#`は不正な文字です。

`//!`と`///`は文書コメント、`////`は通常のコメントです。コンパイルの意味は変わりません。
配置やリンクのエラーだけで`rukbat check`が失敗することはありません。
関連付け、Markdown、検査、整形時の保持規則は[文書生成ガイド](DOCUMENTATION.md)を参照してください。

<a id="scope-and-execution"></a>

## スコープと実行

各モジュールは依存先の初期化後、トップレベルの文を1回実行します。
関数は宣言順に関係なく使え、定義元モジュールの変数を参照します。
ブロックは子スコープを作ります。外側の変数を同名で隠せますが、同じスコープ内で再宣言はできません。

`return`は関数内だけで使えます。戻り値が`void`でない関数は、到達可能なすべての経路で値を返すかthrowする必要があります。
void関数は末尾のreturnを省略できます。
式と関数引数は左から右へ評価し、`&&`と`||`は短絡評価します。

構造体、配列、辞書は変更可能な値型です。
内部の値は更新できますが、代入、引数渡し、戻り値、他の値への格納では再帰的にコピーします。
コピーを変更しても、コピー元の格納先は変わりません。

<a id="types-nullable-values-and-conversions"></a>

## 型、null許容値、変換

プリミティブ型は`int`、`float`、`string`、`bool`です。
intは符号付き64ビット整数、floatは有限のIEEE 754 binary64値です。`void`は戻り値専用です。
ユーザー定義の`struct`、型付き配列`T[]`、型付き辞書`dict[K, V]`、null許容型`T?`もあります。

標準モジュールには通常の構造体と、不透明な不変型もあります。
不透明型は通常の変数、引数、戻り値、フィールド、配列、辞書、null許容型として使えますが、公開フィールドや構造体リテラルを持ちません。
APIと変換規則は[標準ライブラリ](STDLIB.md)で定義します。

| 型 | 言語上の扱い |
|---|---|
| `json.Value` | 構造が未知のJSON。動的なメンバー・インデックスアクセス、等値比較、直接表示は不可。JSON nullはRukbatのnullとは別の値。更新は新しい値を返す。 |
| `csv.Row` | ライブラリ関数で読み書きする不変の行。等値比較と直接表示は不可。`csv.Table`は`columns: string[]`と`rows: csv.Row[]`を持つ通常の構造体。 |
| `encoding.Encoding`, `hash.Algorithm` | 検証済みの読み取り専用定数と同型の等値比較。順序比較、文字列・数値への暗黙変換は不可。外部名には明示的なparse/name操作を使う。 |
| `log.Level` | 検証済み重要度定数と、nullでない同型の等値比較。順序、算術、フィールド、構造体リテラル、暗黙変換は不可。`log.Logger`はコピー可能な設定フィールドを持つ通常の構造体。 |
| `http.Body`, `http.Method` | 不変の応答バイト列と検証済みメソッド定数。等値比較はMethodのみ。HTTPの要求・オプション・結果は通常の構造体。ステータス定数は読み取り専用int。 |
| `fs.Lines` | 不変のファイル行記述子。forが個々の走査を管理。等値比較、直接表示、公開フィールドは不可。 |
| `re.Pattern` | 検証済みの不変の正規表現。検索のタイムアウトを明示する。等値比較、直接表示、公開フィールドは不可。`re.Match`は一致文字列、コードポイント単位の範囲、null許容のキャプチャ文字列を持つ通常の構造体。 |
| `datetime.Timestamp`, `datetime.Date`, `datetime.Duration`, `datetime.Zone` | 明示的な変換・算術。同型の等値比較と、Zone以外の順序比較。名前付きゾーンは読み取り専用定数。 |

encoding、hash、log.Level、HTTPの不透明型、fs.Lines、re.Pattern、datetime型は、表示・JSON・PowerShellとの受け渡しで再帰的に拒否します。
JSON/CSVの更新は元の値を維持し、通常のコンテナーのコピーも独立します。
ZIPは通常の構造体`zip.Options`と`zip.Entry`を公開します。

```rukbat
nickname: string? = null
values: string?[] = ["one", null]
optional_values: string[]? = null
```

`T`はnullを含まず、`T?`はTの値かnullを持ちます。TとnullはT?に変換できます。
T?からTへの暗黙変換はありません。`T??`と`void?`は不正です。`x := null`も具体的な型を推論できないため不正です。
配列要素の型は不変です。`string[]`から`string[]?`には変換できますが、`string?[]`には変換できません。
`int[]`から`float[]`への変換もありません。

intとfloatはnull許容値を含めて暗黙変換しません。標準ライブラリの`math`による明示的な変換を使います。

null許容の変数・引数は、直接の`== null`または`!= null`検査で型を絞り込めます。
null側の分岐で早期returnまたはthrowした場合も、その後の経路で絞り込みます。代入時には絞り込み状態を再計算します。
構造体フィールド、配列要素、その他の複雑な式は絞り込みません。

モジュール変数も絞り込めます。ただし同じモジュールの通常の関数を呼ぶと、その関数が変数を変更する可能性があるため絞り込みを無効にします。
`print`、標準の組み込み関数、別モジュールの関数は現在のモジュールの絞り込みを無効にしません。

絞り込み前のT?で使える操作は、nullリテラルとの直接比較、互換性のあるnull許容の格納先への格納、null許容値としての引数渡し・return、対応型のJSON変換、null許容値に対応した外部との受け渡しです。
2つのnull許容式の一般的な等値比較は定義しません。

<a id="numbers-and-equality"></a>

## 数値と等値比較

浮動小数点リテラルには`1.0`、`1e3`、`1E3`、`1.5e-2`を使えます。`.5`と`1.`は不正です。
算術・比較の両オペランドは同じ数値型でなければなりません。`%`はintだけに定義します。

整数・浮動小数点のゼロ除算は実行時Errorです。
floatリテラル、演算結果、外部値がNaNや正負のInfinityなら拒否します。
整数演算は範囲を検査し、オーバーフロー時は桁の折り返しや型昇格をせずErrorにします。
整数除算はゼロ方向に切り捨て、剰余の符号は被除数と同じです。最小整数を-1で割るとErrorですが、その剰余は0です。
整数の範囲は-9223372036854775808～9223372036854775807です。
その他のfloat演算は、binary64で表現できる最も近い値に丸めます。ちょうど中間の場合は、仮数の最下位ビットが0になる側を選びます。非正規化数と、演算でゼロにアンダーフローすることを許可します。
正と負のfloatのゼロは等しいと判定します。

プリミティブ値の等値比較には、互換性のあるnullでない値が必要です。文字列は大文字小文字を区別します。
intとfloatの混在比較は拒否します。構造体、配列、辞書の等値比較は定義しません。
null許容値はnullと直接比較できます。

<a id="errors"></a>

## エラー

実行時エラーは、エントリソースのディレクトリからの相対ソース名と元の行番号を報告します。
区切りは`/`に統一し、そのディレクトリ外のインポートには`../`を使います。
生成エラーメタデータには開発環境の絶対ソースパスを埋め込まず、実行時のソースファイルも不要です。
コンパイル時の診断には実際のソースパスを使います。
ユーザーが文字列リテラルに書いた絶対データパスなどは保持し、伏せ字にはしません。

`Error`は`message: string`フィールドを持つ組み込み値型です。
throwはErrorを受け取り、tryには型を指定しないcatch変数を1つだけ置けます。finallyはありません。
PowerShellの失敗、不正な外部値、算術エラー、配列範囲外も同じErrorの経路で処理します。
再throwは元のソース位置を保持します。
`throw Error { message: "invalid configuration" }`のように、通常の構造体リテラルで作成します。それ以外は通常の値型です。

<a id="types-and-expressions"></a>

## 型と式

`import array`で、新しい配列を返すスライス、削除、安定ソートを使えます。要素型は型付き配列の引数から推論します。
範囲検査、対応するキー型、順序規則は[標準ライブラリ](STDLIB.md#array)を参照してください。

配列の長さは変更できます。`values.append(value)`は末尾に1値を追加してvoidを返します。
appendは`=`の左辺にできる配列だけに使えます。変数、または変数を起点にした構造体フィールド・配列インデックスの連鎖です。
関数の戻り値などの一時値は変更できません。追加値は要素型と互換性が必要です。

代入やappendの対象に含まれる各インデックス式は、左から右へ1回ずつ評価します。
入れ子の更新は一時コピーではなく、指定した格納先に書き戻します。

- `+`は2つの文字列を連結します。
- 配列リテラルは`[value, ...]`です。`values.append(value)`で要素を増やせます。
- 文脈から型が決まる配列リテラル（`name: T[] = [...]`やT[]型の引数）は、標準の暗黙変換で各要素をTに変換します。文脈の型がなければ全要素が同じ型である必要があり、`[1, 2.0]`は拒否します。互換性のない型の混在はコンパイルエラーです。型を明示した空配列`items: string[] = []`は使えます。
- `items[index]`は要素の読み書き、`items.length`は読み取り専用の長さです。

<a id="dictionaries"></a>

## 辞書

`dict[K, V]`は動的なキーに値を対応付けます。Kはnullでないstringかintだけです。
Vにはnull許容値、構造体、配列、辞書、標準の不透明値を含む格納可能な型を使えます。
voidと、辞書の値を経由して再帰する構造体の循環は拒否します。型引数KとVは不変です。異なるKやVを持つ辞書型には暗黙変換できません。
dictは専用の組み込み型コンストラクターであり、モジュールや汎用ジェネリック機能ではありません。
構造体にdictという名前は付けられませんが、他の規則に適合する変数やインポート別名には使えます。インポートは不要です。

```rukbat
counts: dict[string, int] = {}
counts["error"] = 1
if counts.has("error") {
    counts["error"] = counts["error"] + 1
}
for key in counts.keys() {
    print(key)
    print(counts[key])
}
counts.remove("error")
print(counts.length)
```

リテラルは`{key: value, ...}`で、キーには式を使え、末尾のカンマは任意です。
`ports := {"http": 80, "https": 443}`は`dict[string, int]`を推論します。識別子キーはその変数の値を使います。
文脈の型がなければ最初の組でKとVを決め、以後は完全に同じ型でなければなりません。
`{}`やnull値には、宣言、引数、return、フィールド、外側のリテラルから辞書型が与えられる必要があります。
構造体リテラルには引き続き型名を明示します。

| 操作 | 結果と動作 |
|---|---|
| `d[key]` | V。キーがなければ、Vがnull許容型でもError。 |
| `d[key] = value` | 書き込み可能な格納先に挿入または置換。 |
| `d.has(key)` | bool。格納値がnullでもtrue。 |
| `d.remove(key)` | void。書き込み可能な格納先から削除。存在しないキーでも成功。 |
| `d.keys()` | 挿入順の独立したK[]スナップショット。 |
| `d.length` | 読み取り専用のint要素数。 |

メソッドの位置引数は表に示した数だけです。
文字列キーは大文字小文字を区別する序数比較を使い、正規化、前後空白の除去、パス比較はしません。
空文字列と符号付き64ビット整数の全範囲を使えます。
置換は位置を保ち、削除後に再挿入すると末尾に移ります。この順序はPowerShell 5.1と7で共通です。

文字列または符号付き整数のリテラルキーの重複はコンパイルエラーです。それ以外の重複は構築時のErrorになります。
各組は記述順にキー、値を評価してから重複を検査し、それ以前の副作用は取り消しません。
インデックスへの代入は既存キーを置換します。`:=`でインデックス先を宣言できません。

通常の値コピーは再帰的です。`user := users[id]`は格納された構造体をコピーし、`users[id].name = "Taro"`は格納先のフィールドを更新します。
変数を起点とする辞書インデックスも書き込み可能なパスです。
起点がconstなら挿入、置換、削除、入れ子の変更を拒否し、構造体メソッド経由の変更も含めます。
関数が返した一時値は変更できません。途中のキーは存在する必要があり、末端の辞書インデックスへの代入だけが挿入します。
入れ子の値は自動生成しません。キー・インデックス式は左から右へ1回ずつ評価します。

走査には`for key in d.keys()`を使います。
辞書を変更してもキーのスナップショットは変わりませんが、`d[key]`は現在の内容を読むため、削除後には失敗する場合があります。
内容も固定したい場合は先にdをコピーし、ソート順に読む場合は`array.sort(d.keys())`を使います。
辞書の等値比較と直接のprint/eprintは定義しません。
hasは格納されたnull許容値を絞り込まないため、変数に読み出してnullと比較してください。
null許容の辞書変数には通常の絞り込み規則を使います。

<a id="control-flow"></a>

## 制御フロー

制御構文は`if` / `else`、`for item in items`、`while condition`、`break`、`continue`、`return`です。
whileの条件はboolで、各反復の前に評価します。breakは最も内側のforまたはwhileを抜け、continueは次の反復に進みます。
ループは0回の可能性があるため、ループだけでは関数が必ずreturnするとは判定しません。

forの走査対象式はループ開始時に1回だけ評価します。
配列はその時点の値のスナップショットを走査します。ループ本体で元の配列変数を変更しても、appendによる追加を含め、走査する要素やその順序は変わりません。
ループ変数には各要素をコピーします。その変数への代入は元の配列を変更しません。

forはnullでない`fs.Lines`も受け取り、文字列を取り出します。
各ループが独立したファイル走査を管理し、EOF、break、return、外へ伝播するErrorで閉じます。continueでは開いたままです。
return式の評価とコピーはクローズ前に行い、戻り値の出力は後始末に成功した後です。
後始末の失敗は通常のErrorになります。元のErrorと後始末の失敗が重なっても、catchしたErrorのソース位置は保持します。
正常なexitと強制終了ではfinallyの実行を保証しません。
記述子、デコード、先読みの動作は標準ライブラリで定義します。

<a id="structs-and-modules"></a>

## 構造体とモジュール

```rukbat
struct User {
    name: string
    age: int
}

impl User {
    fn is_adult(): bool {
        return self.age >= 20
    }
}

user := User { name: "Taro", age: 30 }
print(user.is_adult())
```

`struct`宣言には、データの形を表すフィールドだけを書きます。
`struct`内のメソッド定義は拒否します。メソッドは`impl StructName { ... }`に書きます。
`StructName { field: value, ... }`という構造体リテラルで値を作ります。
null許容フィールドも含めて全フィールドの初期化が必要です。
フィールドは名前で指定し、順番は問いません。重複、不足、未知のフィールドはコンパイルエラーです。
初期化式は書いた順に左から右へ評価します。

`impl`宣言はモジュールスコープに置き、内部には`fn`によるメソッドだけを書きます。
対象には、同じモジュールで定義したユーザー構造体の名前を、モジュール名を付けずに指定します。
対象の`struct`より前にも後にも書けますが、1つの構造体に定義できる`impl`は1つだけです。
インポートした型、組み込み型、配列、辞書には`impl`を定義できません。`impl`は予約語です。
メソッド名の重複や、フィールドと同じ名前のメソッドは拒否します。

メソッドはfnで定義し、selfを読み書きできます。
selfを更新するメソッドを呼べるのは、代入可能な対象だけです。変数、または変数を起点とする構造体フィールドと配列インデックスの連鎖が該当します。
関数の戻り値などの一時値に対する変更メソッドはコンパイルエラーで、appendと同じ規則です。

インポートは静的で、実行前に解決します。
プロジェクト内の相対モジュールには、明示的な相対`.rukbat`パスと別名を使います。
標準モジュールには標準ライブラリで定義した正式なモジュール名を使います。

<a id="powershell-boundary"></a>

## PowerShellとの境界

生成スクリプトはモジュール初期化の前に、開始時のファイルシステム上の作業ディレクトリと、`$PSScriptRoot`によるスクリプトディレクトリを保存します。
`rukbat run`を含む`powershell -File` / `pwsh -File`の直接実行では、ホストプロセスのカレントディレクトリを使います。
`[`や`]`もパスの文字として扱います。PowerShellの文からスクリプトを呼ぶ場合は、そのセッションのファイルシステム上の場所を使います。
標準ライブラリの相対ファイルパスは、エスケープハッチでPowerShellや.NETのカレントディレクトリを変えても、保存した開始ディレクトリを基準にします。
`process.Options.working_dir`は子プロセスの作業ディレクトリを指定します。その相対指定と実行ファイルの相対パスは、保存した開始ディレクトリを基準にします。
子プロセス限定の環境変数とテキスト入力は標準ライブラリを参照してください。エスケープハッチのコマンドはPowerShellの意味に従います。

ローカルインポートは、インポート元ソースからのコンパイル時の相対パスです。実行時の作業・スクリプトディレクトリとは関係しません。
配布した`.ps1`の隣のデータには`path.script_dir()`を使います。
生成物は別のPowerShellプロセスでファイルとして実行してください。
通常のソース位置はエラー報告用で、VS Codeデバッガーは[デバッグガイド](DEBUGGING.md)に記載した開発用メタデータを別途使います。

`path.working_dir()`は保存した開始ディレクトリを返します。
`path.resolve(base_dir, value)`はプログラムの作業ディレクトリを変えずに、明示した絶対ディレクトリを基準にパス値を解決します。
`path.relative(base_dir, target)`は絶対パス同士の相対パスを求めます。
いずれもファイルシステムの実体を調べません。Windowsパスの規則は標準ライブラリで定義します。

`powershell<T>(command, ...)`は、標準APIで扱わないPowerShell操作への明示的なエスケープハッチです。
戻り値をTに照らして検査します。単一値ならちょうど1値が必要で、T[]なら値を配列に集めます。
PowerShellの失敗や互換性のない結果は実行時エラーです。

PowerShellの引数・結果型には、辞書や、`json.Value`、`csv.Row`、`cli.Result`、`encoding.Encoding`、`hash.Algorithm`、`log.Level`/`log.Logger`、`re.Pattern`、datetime型、HTTPのBody/Methodなどの不透明値を含められません。
外部コマンドのJSONは文字列として受け取り、json.parseで読みます。
文字コードはencoding.name(value)を渡し、返されたテキストはencoding.parseで解析します。

出力なしと、明示的な`$null`1個の出力は区別します。
TとT?では出力なしはErrorで、明示的な$nullを受け取れるのはT?だけです。
T[]では出力なしが`[]`になります。$null1個はT?[]なら`[null]`、T[]ならErrorです。
null許容配列T[]?は明示的な$null1個を受け取れますが、出力なしはErrorです。
外部のfloat値は数値かつ有限でなければなりません。

生成スクリプトにRukbatコンパイラやPowerShell 7のインストールは不要です。
PowerShellは実装先であり、Rukbatの構文や標準APIの意味を定めるものではありません。

実行にはFullLanguageが必要です。
生成スクリプトはユーザー処理の前に確認し、制限されたモードでは診断を出して0以外で終了します。実行ポリシーは緩和しません。
プロセス封じ込めと復旧可能なファイル移動に必要なOS・ファイルシステムの追加要件は標準ライブラリに記載します。

<a id="formatting"></a>

## 整形

`rukbat fmt`は名前解決や型検査をせず、構文を解析します。
ディレクトリ指定では拡張子`.rukbat`の大文字小文字を区別せず、`.git`、`bin`、`obj`、リンク、ジャンクションを除外します。
空ディレクトリは成功します。構文・I/Oエラーを報告しても残りを処理し、正常なファイルは書き換え、不正なファイルはそのまま残します。
構文エラーとI/Oエラーが両方ある場合、終了コード2を優先します。

整形形式は固定で、設定項目はありません。
インデントは空白4個、1行1文、二項演算子の前後とカンマ・コロンの後に空白を置き、区切り文字の内側には余分な空白を置きません。
開き波括弧は宣言・制御文と同じ行に置き、else/catchは直前の閉じ波括弧と同じ行に置きます。
コメントと文・コメント間の空行を保持し、連続空行は1行にまとめます。先頭の空行と、ブロックの波括弧直内側の空行は削除します。
BOMなしUTF-8、LF改行で書き、末尾には余分な空行を付けずLF1個（`\n`）を置きます。空ソースは`\n`になります。

インポート群と他の文の間、および同一ブロックに別の文がある場合の関数・構造体宣言・impl宣言・制御文（if、for、while、try）の前後には空行を1行置きます。
`impl`内のメソッド同士も空行1行で区切ります。構造体のフィールドや単純な文が続く場合は、ソースで空行を入れていなければ連続させます。
ブロックの端、ifとelseの間、tryとcatchの間には空行を入れません。
直前のコメントは後の文に、行末コメントは前の文に付けたままにします。

構造体リテラルは波括弧内をインデントします。閉じ波括弧は、後続するカンマ、メンバーアクセス、インデックス、式を閉じる区切りと同じ行に置きます。
式の継続行は通常1行にまとめます。行コメントのために継続が必要なら、空白4個を追加して字下げします。
閉じる区切りは外側ブロックに揃えます。
コメントの位置によっては、開き波括弧、else、catchも別行に置きます。
文字列内の実際のCR/LFは`\r`/`\n`エスケープに変え、値を保ちつつソースの改行形式を統一します。
2回整形しても1回目と同じ結果になります。
