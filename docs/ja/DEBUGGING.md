# VS CodeでRukbatをデバッグする

[English](../../docs/DEBUGGING.md) | [日本語目次](README.md)

拡張機能はWindows PowerShell 5.1を使って`.rukbat`ソースをデバッグします。
同梱版VSIXには、別のデバッガー、PowerShell拡張機能、.NETのインストールは不要です。
チェックアウトした開発環境では、言語サーバーと同じコンパイラ設定を使います。

<a id="start-a-session"></a>

## セッションを開始する

1. 対応するRukbatのVSIXをインストールし、VS Codeのウィンドウを再読み込みします。
2. 信頼済みワークスペースで、保存済みのエントリソース`.rukbat`を開きます。
3. エディタ左端またはF9で、実行可能な文にブレークポイントを設定します。
4. F5を押し、選択を求められたら **Rukbat** を選びます。**Rukbat: Debug File** からも開始できます。

拡張機能はコンパイル前に、インポート先を含む開いているファイルを保存します。
コンパイルエラーがある場合は実行しません。
最初の停止位置は最初の実行可能な文の直前です。インポート先モジュールの初期化中に止まる場合もあります。
F5で続行、F10でステップオーバー、F11でステップイン、Shift+F11でステップアウト、Shift+F5で終了します。
ステップ実行はRukbatの文をたどり、生成したヘルパーや標準ライブラリの内部を飛ばします。
呼び出し先のブレークポイントでは、ステップオーバー中でも停止します。
ステップアウトは呼び出し元の次の実行可能な文で停止し、式の途中では止まりません。

Variablesペインには、初期化後の **Locals** と **Module** の値を表示します。
配列、辞書、構造体はRukbatの名前で展開できます。辞書は挿入順と読み取り専用のlengthを表示します。
constは読み取り専用として表示し、プリミティブ値は型を維持します。浮動小数点数も再変換で元の値を保てる精度で表示します。
Call Stackは、引数、`self`、ループ・catchの束縛名、同名で隠されたローカル変数、停止中の呼び出し元、インポート先の初期化スコープを保持します。
プログラムの標準出力と標準エラー出力はDebug Consoleに表示されます。

<a id="arguments-and-working-directory"></a>

## 引数と作業ディレクトリ

エントリソースや引数を固定したい場合は、`.vscode/launch.json`を作成します。

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "rukbat",
            "request": "launch",
            "name": "Debug Rukbat",
            "program": "${workspaceFolder}/main.rukbat",
            "cwd": "${workspaceFolder}",
            "args": ["config.json", "a literal argument with spaces"],
            "stopOnEntry": true
        }
    ]
}
```

引数はそのままの文字列であり、シェルコマンドとしては解釈しません。
既定の作業ディレクトリは選択したワークスペースフォルダーです。フォルダーがなければエントリソースのディレクトリを使います。
デバッグ用スクリプトもエントリソースと同じ場所に作るため、`path.script_dir()`はそのディレクトリを示します。
セッションごとに専用の出力を作り、PowerShellホスト終了後に削除します。通常ビルドの`.ps1`は上書きしません。
**Run Without Debugging** は同じ起動設定と引数を使い、途中で停止せず実行します。

<a id="limitations"></a>

## 制約

- 行ブレークポイントは実行可能な文の直前で停止します。関数・構造体の宣言、インポート、コメント、閉じ括弧には停止しません。行ブレークポイントはエディタ左端に、列を明示したブレークポイントは行内マーカーで表示します。同じ行に複数の文がある場合、その行ブレークポイントはすべての文を対象にします。
- ウォッチ、ホバー、Debug Consoleでは、`count`、`self.name`、`items.length`、`items[0].name`、`users["id"].name`、`codes[-1]`などの読み取り専用の変数パスを使えます。辞書の文字列キーにはRukbatの引用符とエスケープを使い、整数キーは符号付き64ビットの全範囲を保持します。配列の負のインデックスは使えません。一般の式、関数呼び出し、変数変更、条件付き・ヒット回数・ログ・例外ブレークポイント、アタッチ、再起動要求には対応していません。
- 一時停止は次のRukbatの文で反映されます。実行中のネイティブ呼び出しやPowerShellエスケープハッチを中断しません。終了操作は、ネイティブ処理の待機中でもPowerShellホストを停止します。
- 変数表示の上限は、配列・辞書ごとに100要素、複合値の深さ6段、停止ごとに約2000個の値ノード、文字列ごとに4096文字です。不透明な標準ライブラリ値は型名だけを表示し、内部プロパティの公開や変換関数の呼び出しは行いません。
- 標準入力は閉じており、対話的なターミナル入力には対応しません。エスケープハッチのコードは通常どおり動きますが、ソース単位のステップ実行対象にはなりません。
- デバッグはチェックポイントを追加するため、実行タイミングが変わります。配布と最終的な運用確認には通常ビルドを使ってください。
- セッション中のソース編集は、次のセッションから反映されます。

<a id="compiler-metadata"></a>

## コンパイラのメタデータ

`rukbat build main.rukbat --debug`は`main.ps1`と`main.ps1.rukbat-map.json`を生成します。
既存の配布用ファイルを残す場合は`rukbat build main.rukbat --debug --output session.ps1`を使います。
付随するマップファイルには、開発用ソースの絶対パス、実行可能なソースと生成コードの位置、参照可能な解決済み変数名、型・フィールド情報が含まれます。エディタ開発用の情報です。
デバッグ用`.ps1`自体はマップやデバッグホストなしでも実行でき、チェックポイントに外部ランタイム依存はありません。

通常の`rukbat build`と`rukbat run`はデバッガー用状態もマップファイルも出力しません。
生成スクリプトは単独実行可能で、Windows PowerShell 5.1に対応します。
デバッガーはPowerShellの行ブレークポイントアクションと、プログラムの標準ストリームとは別のローカル名前付きパイプを使います。
実行ポリシーは変更しません。
