# Rukbat 0.1.0 preview

The first public preview of Rukbat, a small, statically typed language for Windows
system scripting. It compiles `.rukbat` sources to standalone Windows PowerShell
5.1 scripts. Generated scripts do not require Rukbat or its bundled authoring runtime.

## Downloads and first run

Choose a package from this release's assets:

| Asset | Contents |
|---|---|
| `rukbat-0.1.0-win32-x64.vsix` | VS Code extension with compiler, language server and debugger. |
| `rukbat-0.1.0-win-x64.zip` | Portable CLI, bundled .NET runtime, documentation and examples. |
| `SHA256SUMS` | SHA-256 hashes of the VSIX and ZIP. |

For VS Code 1.82 or later, use **Extensions: Install from VSIX**, open a trusted
folder and save a `.rukbat` file. Use **Rukbat: Run File** from the Command Palette.

For the CLI, extract the entire ZIP and open a terminal in its directory:

```powershell
.\rukbat.exe --version
.\rukbat.exe doctor
.\rukbat.exe run .\example\hello.rukbat
.\rukbat.exe build .\example\hello.rukbat
powershell -NoProfile -File .\example\hello.ps1
```

Neither package requires a separately installed .NET SDK or runtime.

## Included in this preview

- Static checking, explicit procedural control flow, functions, structs, arrays,
  dictionaries, nullable values, constants and local modules.
- Standard APIs for files and paths, text and regular expressions, CSV/JSON,
  processes, encoding, dates, HTTP, archives, hashes, logging and CLI arguments.
- `check`, `build`, `run`, `fmt`, `test`, `doc`, `doctor` and `lsp` commands.
- VS Code diagnostics, completion, navigation, rename, formatting and source debugging.
- MIT-licensed Rukbat source; bundled dependencies retain their own licenses.

## Compatibility and limitations

### Verification status

Final acceptance on a clean Windows machine with no separately installed .NET SDK
or runtime and no network access has **not been completed**. This pre-release is
being published with that verification still outstanding.

On the development machine, the extracted CLI ZIP and VSIX runtime passed checks
for CLI commands and LSP with system .NET removed from the child process PATH and
DOTNET_ROOT redirected to a nonexistent directory. Generated scripts also ran on
Windows PowerShell 5.1 and PowerShell 7 after their source files were removed.
These controlled checks do not replace clean-machine, offline acceptance testing.

### Preview compatibility

This preview is intended for evaluation and feedback. Later 0.x releases may change
syntax, standard-library APIs and tooling behavior. Pin the compiler version for
automation and recheck, rebuild and test sources before upgrading.

- Packages target Windows x64; cross-platform deployment is outside this release's scope.
- Windows PowerShell 5.1 is the execution target. PowerShell 7 is optional.
- Generated scripts require FullLanguage mode; native helpers require Add-Type
  permission. Rukbat does not change execution or application-control policies.
- Process containment requires Windows 10 / Server 2016 or later. HTTP requires
  .NET Framework 4.7.1 or later on the target.
- Standalone scripts may still need explicitly used data, external executables,
  permissions or network services.
- There is no package manager. User modules use relative source-file imports.

Documentation is included in the CLI ZIP. See the repository's
[English README](https://github.com/shuuuumai96/rukbat#readme) or
[Japanese README](https://github.com/shuuuumai96/rukbat/blob/main/docs/ja/README.md)
for guides and examples.

Report problems through [GitHub Issues](https://github.com/shuuuumai96/rukbat/issues).
Include the compiler version, `doctor` output, a minimal source example, and expected
and actual results. Remove credentials and private paths before posting.
