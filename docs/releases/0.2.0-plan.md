# Rukbat 0.2.0 preview release plan

[日本語](../ja/releases/0.2.0-plan.md)

Decision date: October 31, 2026. Target release date: November 14, 2026 (Japan time).
This page records the agreed plan; it does not announce an available 0.2.0 package.
Update this page and its Japanese translation when the schedule or scope changes.

## Scope

0.2.0 will be an evaluation preview focused on the separation of struct fields and
`impl` methods, existing-feature bug fixes, and verification of the distributed packages.
New feature work is outside this release's scope. The version number marks a source
compatibility change; it is not a declaration of production stability.

## Schedule

All dates below are in 2026, Japan time.

| Dates | Work | Completion criteria |
|---|---|---|
| October 31–November 2 | Freeze scope | List changes, compatibility breaks, and known bugs; stop adding features. |
| November 3–7 | Investigate and fix serious bugs | Prioritize incorrect generation, lost updates, false success, file operations, and process termination. Add regression tests for fixes. |
| November 8 | Build the release candidate | Align compiler and extension versions at 0.2.0; build CLI ZIP and VSIX from one recorded commit. |
| November 9–12 | Verify the candidate | Complete the full test suite, PowerShell 5.1 and 7 execution checks, editor checks, package tests, and clean-Windows acceptance. |
| November 13 | Decide whether to publish | Review evidence, remaining issues, migration guidance, and checksums. |
| November 14 | Publish 0.2.0 preview | Match tag, tested commit, and packages; update recommended download links. |

## Release conditions

- Resolve known bugs that can corrupt data, generate incorrect results, lose updates,
  or report success after a failed operation.
- Run the full test suite and execute generated scripts on Windows PowerShell 5.1
  and PowerShell 7. Include practical CSV/JSON, filesystem, and external-process scenarios.
- Verify check/build/run/test/fmt/doc/LSP from the actual ZIP and VSIX. Check VS Code
  diagnostics, completion, formatting, run/build, and debugging.
- Complete acceptance on a clean Windows machine without a separately installed
  .NET SDK/runtime and without network access. Execute generated scripts on a separate
  target without the compiler. Follow [distribution acceptance](../DISTRIBUTION.md#release-acceptance).
- Publish migration instructions and document deferred issues with their impact
  and available workarounds. Minor editor/display/diagnostic wording issues may be deferred.

Record the source commit and verification results for each candidate. Any candidate
change requires new packages and renewed verification of the affected paths and packaging.
Only publish the exact packages that passed acceptance.

If a serious known bug remains or required verification is incomplete on November 13,
postpone the release. The next target is November 21, subject to the same conditions.
Update this plan and the README announcement when postponing; do not waive checks to meet a date.

## 0.1.0 policy

- Preserve the existing tag, ZIP, VSIX, and SHA256SUMS for reproducibility. Do not
  replace published packages with different bytes under the same version.
- Keep 0.1.0 identified as an initial evaluation preview. Add notices to its release
  notes; list a specific known bug only after confirming that the released version is affected.
- Do not schedule a routine 0.1.1. Concentrate maintenance on 0.2.x. If serious data
  corruption or a security issue is confirmed before 0.2.0, assess an emergency fix
  or withdrawal of affected downloads separately.
- End maintenance of 0.1.0 when 0.2.0 is published. Mark it as superseded, retain its
  downloads, and link to the replacement and migration guidance. Recommend 0.2.0
  in the English/Japanese READMEs and installation guides.

## Migration guidance required for publication

Move methods declared inside a struct into an adjacent `impl StructName` block in
the same module. Structs containing only fields need no `impl`. Explain the new
reserved word and any other confirmed compatibility changes in the final release notes.

Pin the chosen compiler version, update sources, run `check` and tests, rebuild,
and validate the generated scripts before replacing deployed artifacts. Updating
the compiler alone does not fix previously generated `.ps1` files.

## Announcement and current status

This document is the repository's release-plan announcement. Link to it from both
READMEs and the 0.1.0 release notes. At publication, create the GitHub pre-release
with final release notes and verified assets, then update the old release's notice
and download guidance. Editing this repository does not itself update GitHub release metadata.

The schedule and policy above are agreed. Full release acceptance remains pending;
the focused tests already run for individual fixes do not establish release readiness.
