# Rukbat 0.2.0 preview release plan

[日本語](../ja/releases/0.2.0-plan.md)

Original target: November 14, 2026 (Japan time). The target passed before acceptance
was complete. On November 20, the maintainer waived clean-Windows offline acceptance
for this preview. The release notes disclose the unverified environment and ask users
to evaluate the preview at their own risk. The other release conditions still apply.

## Scope

0.2.0 will be an evaluation preview focused on the separation of struct fields and
`impl` methods, omitted return-type annotations meaning void, existing-feature bug fixes,
and verification of the distributed packages. The void declaration rule was added to
the scope on November 1, before the November 2 scope-freeze checkpoint. After that
checkpoint, additional features are outside this release's scope. The version number
marks source compatibility changes; it is not a declaration of production stability.

## Release conditions

- Resolve known bugs that can corrupt data, generate incorrect results, lose updates,
  or report success after a failed operation.
- Run the full test suite and execute generated scripts on Windows PowerShell 5.1
  and PowerShell 7. Include practical CSV/JSON, filesystem, and external-process scenarios.
- Verify check/build/run/test/fmt/doc/LSP from the actual ZIP and VSIX. Check VS Code
  diagnostics, completion, formatting, run/build, and debugging.
- Execute generated scripts on a separate target without the compiler. Follow
  [distribution acceptance](../DISTRIBUTION.md#release-acceptance), with the
  clean-Windows offline exception for this preview described above.
- Publish migration instructions and document deferred issues with their impact
  and available workarounds. Minor editor/display/diagnostic wording issues may be deferred.

Record the source commit and verification results for each candidate. Any candidate
change requires new packages and renewed verification of the affected paths and packaging.
Only publish the exact packages that passed acceptance.

Publish once the release conditions are met. The original November 14 and fallback
November 21 targets were conditional on acceptance.

## Explicit void removal in 0.3.0

Decision date: November 1, 2026. The compatibility window is 0.2.x only.
During 0.2.x, function and method declarations may still use `: void`, and `fmt`
converts them to the canonical omitted form. In 0.3.0, remove acceptance of that
annotation and its formatter conversion; report a syntax error directing users
to omit the return-type annotation. Do not retain a formatter-only legacy parser.

Announce this removal in the 0.2.0 release notes. Users must run the 0.2.x formatter
before upgrading to 0.3.0. Before publishing 0.3.0, migrate repository source examples,
documentation, and snippets; retain explicitly labeled historical examples where needed.
The removal affects only `: void` annotations on function/method declarations.
Internally, the compiler still represents the absence of a return value as void,
so it can reject uses such as assigning a call with no result to a variable.
`powershell<void>` remains the explicit instruction to discard PowerShell output
instead of receiving it as a Rukbat return value; failures still raise Error.
Void is not a type of value that can be stored in a variable or field.
Standard API references may still use `: void` to describe the absence of a return value.

## 0.1.0 policy

- Preserve the existing tag, ZIP, VSIX, and SHA256SUMS for reproducibility. Do not
  replace published packages with different bytes under the same version.
- Keep 0.1.0 identified as an initial evaluation preview. Add notices to its release
  notes; list a specific known bug only after confirming that the released version is affected.
- Do not schedule a routine 0.1.1. Concentrate maintenance on 0.2.x. If serious data
  corruption or a security issue is confirmed before 0.2.0, assess an emergency fix
  or withdrawal of affected downloads separately.
- End maintenance of 0.1.0 when 0.2.0 is published. Mark it as superseded, retain its
  downloads, and link to the replacement and migration guidance. Recommend 0.2.0
  in the English/Japanese READMEs and installation guides.

## Migration guidance required for publication

Move methods declared inside a struct into an adjacent `impl StructName` block in
the same module. Structs containing only fields need no `impl`. Explain the new
reserved word and any other confirmed compatibility changes in the final release notes.

Pin the chosen compiler version, update sources, run `check` and tests, rebuild,
and validate the generated scripts before replacing deployed artifacts. Updating
the compiler alone does not fix previously generated `.ps1` files.
